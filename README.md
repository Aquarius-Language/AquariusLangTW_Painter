# 星泉塗鴉室

使用 AquariusLang（星泉）編寫的繁體中文繪圖專案。工具與編輯流程參考所提供的小畫家畫面，介面採另一張參考圖的深色、薄荷綠、細邊框、星點與軌道風格。

**繪圖、工具、文件、圖層與介面邏輯皆在三份 `.aqua` 原始碼中。** 正式星泉編譯器先生成 `.wasm` WebAssembly，再輸出至相對目錄 **`./web`**；瀏覽器執行 WebAssembly，沒有用 JavaScript 重寫繪圖應用程式。

三份 AquariusLang `.aqua` 原始碼均位於專案根目錄；輔助建置與預覽的 `.mjs` 腳本集中於 `工具/`，驗證腳本位於 `測試/`。

## 開啟已建置版本

在本專案目錄執行：

```powershell
.\啟動.ps1
```

開啟 <http://localhost:8080>。另一種方式：

```powershell
node 工具/預覽伺服器.mjs 8080
```

請透過 localhost 或 HTTPS 提供整個 `web` 資料夾；直接雙擊 `web/index.html` 的檔案網址無法載入 WebAssembly 與主機模組。需要瀏覽器能取得 WebGPU 裝置。圖片編碼器、WebAssembly 主機及相關相依套件都在 `web`，不依賴 CDN 或應用程式伺服器。

`啟動.ps1` 使用 PATH 中的 Node.js。伺服器僅綁定本機位址，關閉終端機或按 Ctrl+C 可停止。

## 發佈至 GitHub Pages

在 GitHub 儲存庫的 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。

`.github/workflows/pages.yml` 會在 `main` 分支的 `web/**` 或工作流程檔案更新時，將已提交的 `web` 資料夾直接發佈。也可在 **Actions → Publish web to GitHub Pages → Run workflow** 選擇 `main` 手動發佈。

修改星泉原始碼後，請先執行 `建置.ps1` 並提交更新的 `web` 輸出；發佈流程不會重新編譯原始碼。網站網址為 <https://Aquarius-Language.github.io/AquariusLang_Painter/>，實際部署連結也會顯示於工作流程的 `github-pages` 環境。

### 使用方式

- 上方「檔案」「編輯」開啟完整操作選單；「常用」「檢視」切換工具帶。
- 左側選擇工具，拖曳白色畫布繪圖。右鍵使用次要色彩；色票上右鍵選擇次要色彩。
- 選取後拖曳搬移，拖曳四角調整大小，按「確認」寫入圖層。取消或 Esc 恢復移動前內容。
- 曲線先拖曳起終點，再點選兩個控制點；自訂多邊形逐點建立後按「完成形狀」。
- 文字工具點選位置後輸入；Enter 換行，Ctrl+Enter 完成。文字面板也有完成與取消按鈕。
- 空白鍵按住並拖曳可平移；滾輪縮放。像素格線在四倍以上顯示。
- 圖層排列由下到上合成；點選圓點切換可見性。鎖定或隱藏的目前圖層不能繪圖。
- 為保留透明度使用 PNG／TIFF；為保留圖層使用 **`.aquapaint`**。JPEG／BMP 以白底輸出。

### 文件與資源限制

單邊最多 4096 像素，單張畫布最多四百萬像素，所有圖層合計最多六百萬像素，最多八個圖層。這是本專案為編輯記憶體、分層序列化及瀏覽器穩定性訂的界限，低於部分原生圖片 API 的上限。

復原最多保留十五個狀態，按圖層像素量及 GPU 色彩／深度附件縮減至約 64 MiB 的快照目標，至少保留兩個狀態；最早歷程會淘汰並重用其畫布。快照在 GPU 內複製，不在放開筆畫時讀回整張圖片。關閉頁面即釋放執行階段資源。分層作品保存圖層內容、名稱、可見性、透明度、鎖定與順序，不保存復原歷程、暫時選取或尚未確認的文字。

填色與分層資料驗證由 WebAssembly 執行，大圖可能需要等候。新增畫布範圍以次要色彩補足，已有的透明像素保持透明。畫布及文字輸入主要按桌面操作設計；較小視窗會整體縮放。

## 繁體中文原始碼及固定協定

主程式、作品引擎的變數、函式、參數、關鍵字、呼叫名稱與介面文案均使用繁體中文。函式庫使用官方的繁體中文方法別名；原生功能經根目錄 `星泉介面.aqua` 的中文介面供應。

**現有 AquariusLang 無法讓所有底層識別字完全沒有拉丁字母。** 官方匯入 ID（例如 `Processing`、`Images`、`Files`）、事件、資料欄位、編碼、格式、渲染器與系統字型 ID 尚無完整中文協定別名。`Window` 兩個圖片橋接別名本身也包含 `Processing`，因此只取出函式參照，對外改以中文名稱呼叫。這些必要邊界集中在相容層。副檔名 `png`、`aquapaint` 等也是標準檔案協定，不是程式變數或函式名稱。

原生選檔器明確拒絕中文副檔名，開發時 `.星泉` 產生 `Invalid filename extension`，故分層檔使用 `.aquapaint`；檔名仍可全中文。編譯產生的 JavaScript 主機、WGSL、WASM 與建置／測試的標準工具 API 不屬於星泉應用語法。

## 開發時遇到的語言／函式庫問題

已更新 AquariusLang 核心與桌面／瀏覽器主機；事件錯誤恢復與資源回收由語言主機提供。以下記錄仍適用的語法調整與 API 邊界；新版已將事件錯誤恢復與資源回收納入官方主機：

| 現象 | 解法 |
| --- | --- |
| 省略初始化的迴圈、`--` 不能編譯 | 使用含「變數」初始化的迴圈，減一改為明確指派。這是目前語法限制。 |
| 字串不解譯反斜線跳脫，寫成反斜線加 n 會插入兩個文字 | Enter 換行使用含實際換行字元的多行字串；以 GPU 像素驗證多行文字、不透明背景與逐行底線。 |
| `模組.陣列[索引]` 出現 `Unsupported module member expression` | 改寫成 `(模組.陣列)[索引]`。 |
| `最小值`／`最大值`／`限制範圍` 的結果作陣列索引出現 `Index operator not supported` | 明確轉為取整結果再使用索引；數值型別不是只按數值是否整數判斷。 |
| 不透明打包色彩大於有號三十二位範圍，直接取整會溢位 | 分層驗證改以低十六位檢查整數性，保留合法的無號打包色彩。 |
| 目錄與 API 清單列出「貝茲頂點」「剪切X／Y」，但瀏覽器執行回報 `Identifier not found` | 在星泉中用「貝茲點」取樣建立輪廓，用「套用矩陣」實作傾斜與斜體。 |
| Processing 裁切範圍不隨目前繪圖矩陣縮放／平移 | 本專案把工作區裁切範圍先轉換到主視口座標。 |
| 快速按放 Ctrl 等修飾鍵後，Processing 的即時按鍵狀態與排隊事件不同步 | 使用 `Window.輪詢` 的事件修飾遮罩及佇列，不僅依賴當下的按鍵狀態。 |
| 功能支援記錄的巢狀值是雜湊表 | 以字串鍵讀取，避免將巢狀能力當作模組存取。 |
| 繪圖畫布取得焦點後，文字未送到官方輸入元素 | 開始文字或名稱編輯時重新啟用官方文字輸入，保存目前編輯器及狀態函式參照。 |
| 拒絕選檔／剪貼簿等操作會拋出錯誤，語言沒有例外處理語法 | 註冊官方 Processing 的 `error` 事件；桌面與網頁皆可顯示中文狀態並繼續編輯。 |
| 瀏覽器 Processing 的影像／畫布集合保留物件直到整個執行階段結束 | 官方桌面與網頁主機在影格邊界追蹤執行中環境、原生呼叫參數、閉包、歷程及圖層，回收不再使用的畫布與影像。 |

`工具/網頁封裝.mjs` 保留外殼本地化與本專案的列印服務移除，並載入同目錄的 `即時主機封裝.mjs`。後者調整瀏覽器主機的時間切片、影格排程、GPU 呈現及畫布透明度標記；每次重建均會套用，主機來源不符預期時會明確失敗。事件恢復、指標擷取、快捷鍵與離屏資源管理仍由 AquariusLang 主機處理；測試使用 `host.runtime` 及官方執行狀態。

### 即時互動效能

透明棋盤在文件尺寸改變時建立一次；頂列、工具帶與左側工具列按操作狀態與懸停按鈕快取，縮放及螢幕像素密度改變時重建。繪圖、合成與快取邏輯仍在中文 `.aqua` 原始碼。

瀏覽器 WebAssembly 每執行約 8 ms 才讓出主執行緒，使用訊息通道避免巢狀計時器的額外等待。輸入每批約 8 ms 後可呈現影格，所有拖曳點及按放順序都保留；GPU 最多允許兩個待完成影格。

本機 Edge、1440 × 900 的相同測試在最佳化前／後分別量得：一般重繪平均 **114.8／14.3 ms**；一次集中送入 60 個拖曳點後的第一個影格 **196.7／29.7 ms**；放開筆畫回呼 **22.7／1.3 ms**。整批輸入完成時間 **206.1／164.7 ms**。這是該測試機的結果，快取重建、大型文件及複雜筆刷仍可能較慢。

執行 `node 測試/即時效能.mjs 測試/結果/效能改善後.json` 可重測；`AQUARIUS_WEB_ROOT` 可指定另一個已建置網站作比較。報告包含指標回呼數與像素檢查，確認 60 個拖曳點全部處理。


檢查涵蓋真正的 WebAssembly、GPU 像素、指標操作、快捷鍵、筆刷與形狀、遮罩、文字／組字、圖層、裁切／變換、編碼解碼、下載與重開、列印功能移除、拒絕權限恢復及連續操作資源數量。結果及實際畫面位於 `測試/結果/`。筆壓與輸入法事件使用瀏覽器事件合約，未聲稱測試所有硬體驅動。

最終驗證結果：Edge 與 Chrome 各 **25 組全部通過**，兩者皆無頁面執行錯誤。包含 GPU 快照的透明像素精確復原、重做分支與歷程淘汰，以及垃圾回收後的資源界限。繁體中文識別字檢查通過，包含 668 個變數宣告及 2433 個呼叫／語法節點。報告為 `測試/結果/邊緣瀏覽器驗證.json` 與 `測試/結果/鉻瀏覽器驗證.json`；`測試/結果/介面.png` 為實際初始介面截圖，`測試/結果/檢視介面.png` 為移除列印後的檢視工具帶。

## 專案檔案

```text
星泉塗鴉室.aqua              中文介面、工具及輸入流程
星泉介面.aqua                官方 API 的中文相容邊界
作品引擎.aqua                像素、圖層、選取、變換、歷程與文件
dist/星泉塗鴉室.wasm       已編譯 WebAssembly 套件
web/                        已建置的完整靜態網站及第三方授權
建置.ps1                    可重現的官方編譯流程
啟動.ps1                    本機預覽入口
工具/網頁封裝.mjs           產物本地化及瀏覽器生命週期適配
工具/即時主機封裝.mjs       瀏覽器主機的即時互動效能調整
工具/預覽伺服器.mjs         本機預覽伺服器
測試/                       原始碼與真實瀏覽器整合驗證
```

網站中的第三方函式庫由官方編譯器封裝，授權／告示檔隨 `web` 交付。系統字型不隨網站散布。

## 新版架構建置

建置使用 PATH 中的 `aqua`。執行 `./建置.ps1` 會自動建立 `dist/`，並輸出 `dist/星泉塗鴉室.wasm`、`web/` 網頁與 `dist/星泉塗鴉室.exe` 自包含 Windows EXE。桌面可用 `aqua run dist/星泉塗鴉室.wasm` 執行，網頁由相同檔案輸出。舊 `.bottle` 產物應從原始碼重新編譯。
